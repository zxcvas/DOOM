What it is

FOON is a public host for the 23 December 1997 Linux Doom 1.10 source. The portable C core — simulation, WAD loader, UI, and the original software renderer — stays C. The later compile path is C → WebAssembly.

Pixels stay authentic because colormap lighting, fuzz shadows, palette flashes, and patch drawing remain CPU software. The renderer still writes a 320×200 8-bit paletted framebuffer (screens[0] + PLAYPAL). We do not rewrite r_*.c into a GPU world renderer.

Indices on the CPU. RGB on the GPU.

The compositor is the only modern layer. Palette indices stay on the CPU. After that buffer is complete, the GPU expands the current PLAYPAL LUT to RGB, integer-upscales with nearest sampling (4:3 present, not square pixels), then runs CRT, bloom, and color grade.

  1. 0 320×200 R8 indices
  2. 1 Palette expand
  3. 2 Integer upscale
  4. 3 CRT / bloom / grade

Bring your own IWAD

Game data is not in this repository and never will be. FOON will not host, fetch, or ship commercial WAD files. You supply an IWAD you own — doom.wad, doom2.wad, shareware doom1.wad, or a freely licensed replacement.

No IWAD, no game. Bring your own.

Roadmap

  1. Phase 0 — Host skeleton Emscripten toolchain, play-shell page, IWAD picker, stub I_*.
  2. Phase 1 — Visible pixels Title screen and E1M1 from the software buffer; non-blocking loop.
  3. Phase 2 — Real compositor WebGL present: index texture + palette LUT, integer upscale, 4:3.
  4. Phase 3 — Audio & input Web Audio SFX, pointer-lock mouse, optional gamepad.
  5. Phase 4 — Modern effects CRT, bloom, color grade as toggles; A/B against palette-only.
  6. Phase 5 — Mods (optional) One gameplay slice or PWAD loader UI — not a renderer rewrite.
